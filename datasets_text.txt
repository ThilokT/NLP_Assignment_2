NLP CS60075 Assignment II — Datasets
How to read this document.Every dataset used anywhere across the 11 projects has one entry here: where to
get it, its exact file/field format, its official splits (or how to construct one if it has none), any preprocessing you
must do before using it, and – separately for every task that uses it – exactly how it is meant to be used in that
task. A dataset reused by more than one project (e.g. UD English EWT, used in Projects 2, 3, and 5) is
documented in full only once, at its first appearance; every later reuse is a short entry that points back to that first
entry and states only what is genuinely different about how the later project uses the same file. Section numbers
below match the “companion Datasets document, SectionN” references already given in the Projects document.

Dataset 1.1 — WikiT ext-2
Source
https://huggingface.co/datasets/Salesforce/wikitext, configurationwikitext-2-raw-v1. Load with
load dataset("Salesforce/wikitext", "wikitext-2-raw-v1"). License: CC-BY-SA-3.0.
Format
A single text column. Each example is one line of raw Wikipedia article text as it appears in the article, including
section-heading lines (wrapped in= =) and blank lines separating articles.
Field Type Meaning
textstring One line of raw article text, a heading line, or an empty string (article separator).
Splits
Split Size Notes
train≈2.09M tokens Use for all training in Tasks 1–3.
validation≈218K tokens Hyperparameter tuning only (k,λ, checkpoint selection). Never touch this for final
numbers.
test≈246K tokens Final reported perplexity only.
Required Preprocessing
1. Concatenate alltextlines within a split into one long token stream – WikiText’s lines are a storage artifact, not
sentence boundaries.
2. Tokenize with a punctuation-aware whitespace tokenizer and lowercase every token.
3. Build the vocabulary fromtrainonly: keep the 30,000 most frequent tokens; map every other token to<UNK>.
Tokens occurring<2 times in train also map to<UNK>.
T ask 1 use:If assigned this dataset: train n-gram count tables ontrain; tune smoothing hyperparameters on

Dataset 1.3 — Gutenberg (NL TK)
Source
Bundled with NLTK:nltk.download(’gutenberg’), thennltk.corpus.gutenberg. A small collection of 18 complete
public-domain English texts (e.g. Austen’sEmma, Melville’sMoby Dick, several Shakespeare plays),≈2.6M words to-
tal.
Format
nltk.corpus.gutenberg.raw(fileid)returns the full raw text of one work;nltk.corpus.gutenberg.fileids()lists
all 18 file identifiers (e.g.austen-emma.txt).
Field Type Meaning
(no tabular fields — each item is one complete literary text, not a structured record)
Splits
Split Size Notes
all 18 texts≈2.6M words No official split; construct your own bywhole file, not by token position (next column).
Required Preprocessing
1. Split by file, not by concatenating everything and cutting at a token count: shuffle the 18 file IDs once with a fixed
seed, and assign roughly 80% offilesto train, 10% to validation, 10% to test. Splitting by whole file (rather than
slicing one continuous stream) avoids near-duplicate context leaking across splits, since different chapters of the
same novel are highly self-similar in vocabulary and style.
2. Concatenate the raw text of each split’s assigned files into one stream; tokenize/lowercase with the same
convention as Dataset 1.1; build the vocabulary from this dataset’s own train split.
3. Gutenberg’s 19th-century prose includes archaic spelling and punctuation conventions (e.g. long dashes, unusual
capitalization) – do not silently strip these as “errors”; treat them as ordinary tokens, the same as any other word.
T ask 1 use:If assigned this dataset: train n-gram count tables on your constructed train split; tune smoothing
hyperparameters on validation; report final perplexity on test.
T ask 2 use:If assigned this dataset: train the A WD-LSTM on your constructed train split; use validation for
checkpoint selection; report final perplexity on test.
T ask 3 use:If assigned this dataset: no additional training – reuse the Task 1/2 models. Use validation only to
tuneλ; report final perplexity on test.

Source
https://huggingface.co/datasets/nyu-mll/blimp(Warstadt et al., 2020). Load with

Format
Each example is oneminimal pair: a grammatical sentence and an ungrammatical sentence differing by one targeted
phenomenon.
Field Type Meaning
sentence goodstring The grammatical sentence.
sentence badstring The minimally-different ungrammatical sentence.
fieldstring Broad category (morphology,syntax,semantics).
UIDstring The specific paradigm name (e.g.wh island).
Splits
One split per paradigm, 1,000 pairs each, no train/validation/test division – a pure evaluation benchmark. This
dataset isnot tied to your group’s assigned dataset above– every group evaluates on BLiMP identically, regard-
less of whether they were assigned WikiText-2, DailyDialog, or Gutenberg for Datasets 1.1–1.3.
Required Preprocessing
1. Select 8–10 paradigms spanning all threefieldcategories – not clustered in one. A reasonable starting set:
anaphor gender agreement,determiner noun agreement 1(morphology);wh island,npi present 1(syntax);
principle A domain 1,drop argument(semantics) – add 2–4 more of your choosing to reach 8–10, and use the
identical selection across Tasks 1, 2, and 3.
2. Tokenize both sentences with the identical tokenizer/vocabulary as whichever dataset your group was assigned
(1.1, 1.2, or 1.3), mapping OOV to<UNK>.
3.Length normalization:always divide each sentence’s total log-probability by its own token count before
comparing the pair.
T ask 1 use:For your best smoothing variant, compute length-normalized log-probability of both sentences per
pair; accuracy = fraction where the model preferssentence good.

Source
https://huggingface.co/datasets/abisee/cnn_dailymail, configuration3.0.0. Load with

Format
Each example is one news article paired with a human-written, multi-sentence summary (the original dataset calls this
fieldhighlights) that has relatively high overlap with the source – many summary sentences are close paraphrases of
individual article sentences, which is exactly why extractive selection is a reasonable strategy on this dataset.
Field Type Meaning
articlestring The full news article text.
highlightsstring The gold summary: several sentences, separated by newlines within the string.
idstring Article identifier. Not a modeling feature.
Splits
Split Size Notes
train≈287,000 articles Fit TF-IDF/IDF statistics and any tuned thresholds here.
validation≈13,000 articles Tunek(Task 1), hyperparameters (Task 2), andm(Task 3) here.
test≈11,000 articles Final reported metrics only.
Required Preprocessing
1. Sentence-splitarticlewith a standard sentence tokenizer (e.g.nltk.sent tokenizeor spaCy’s sentencizer) – this
is the unit both TextRank/LexRank and ROUGE operate over.
2. Splithighlightson its internal newlines to recover the gold summary as a list of sentences (needed for computing
extractive density and compression ratio against a multi-sentence reference).
3. Some articles retain source boilerplate (e.g. a leading(CNN) --byline marker) – strip this before sentence-splitting,
or it can end up selected as a spurious high-centrality “sentence” by TextRank/LexRank.
T ask 1 use:If assigned this dataset: build the TF-IDF sentence graph fromtrain; tunek(and LexRank’s

T ask 3 use:If assigned this dataset: tunemonvalidation; run Task 1’s extractor into Task 2’s trained model on
test; evaluate ROUGE and the factual-consistency proxy against Task 1 and Task 2.
